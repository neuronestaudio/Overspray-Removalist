# The Overspray Removalist — app

Lead-gen site on the Glossed Out template infrastructure. React 19 + Vite 7 + TypeScript,
pre-rendered to static HTML at build time, deployed on Vercel.

The front end is deliberately plain. The infrastructure below is the finished part.

```bash
npm install
npm run dev            # http://localhost:5173
npm run build          # type-check, bundle, SSR bundle, pre-render, sitemap
npm run serve          # serve dist/ exactly as production does
```

## Before this can go live

Two placeholders. Both are load-bearing.

| What | Where | Why it matters |
|---|---|---|
| **GTM container ID** | `index.html` (×2) and `GTM_ID` in `src/lib/site.ts` | Currently `GTM-XXXXXXX`, so nothing is measured |
| **GoHighLevel webhook** | `GHL_WEBHOOK` in `src/lib/site.ts` | Currently `REPLACE_ME`. The form refuses to submit and says so, rather than posting leads nowhere |

Optional, for photo attachments: set `RESEND_API_KEY` (and optionally `QUOTE_TO`,
`QUOTE_FROM`) in Vercel. Without it the lead still reaches the CRM; only the photo email fails.

## How a lead flows

```
visitor lands  ->  captureAttribution()      first touch written to localStorage, gap-fill only
                                              10 ad params + first_landing_page
submit         ->  validate, then POST JSON straight to the GHL webhook
                   payload = form fields + attribution + submission_id
2xx from GHL   ->  dataLayer: quote_form_submit, generate_lead
                   photos POST separately to /api/quote-photos, fire and forget
                   navigate to /thank-you
non-2xx        ->  no events, fields kept, retry message with the phone number
```

Two rules the form is built around, both inherited from the template:

1. **Conversion events fire only after the CRM acknowledges the lead.** An uncaptured lead is
   not a conversion. Reporting it as one corrupts every decision made about ad spend afterwards.
2. **Nothing optional may block a lead.** Attribution returns empty strings when storage is
   blocked rather than throwing. Photos travel in a separate request after the lead is safe.

## Attribution

`src/lib/attribution.ts`. First-touch, not last-touch: the record is written on the first visit
and thereafter only gap-filled. A field holding a value is never overwritten and
`first_landing_page` is never replaced, so a later untagged visit cannot erase what a tagged
visit recorded.

Captured: `utm_source`, `utm_medium`, `utm_campaign`, `utm_content`, `utm_term`, `gclid`,
`gbraid`, `wbraid`, `fbclid`, `msclkid`, plus `first_landing_page` and a per-submission
`submission_id`.

> Ten of these need matching custom fields in the GHL sub-account or they arrive and are
> silently dropped. Create them before spending on ads, not after.

## Analytics

GTM container in `index.html`; events pushed from `src/lib/gtm.ts`.

| Event | Fired by |
|---|---|
| `page_view` | every route change |
| `key_service_page_view` | paths in `KEY_SERVICE_PATHS` (`src/lib/site.ts`) |
| `scroll_depth` | 25 / 50 / 75 / 90%, once each per page |
| `high_intent_time_on_page` | 60s on a page |
| `phone_call_cta_click` + `contact` | any `tel:` click, one delegated listener |
| `quote_form_submit`, `generate_lead` | only after the CRM returns 2xx |

## Rendering

Every route ships **real HTML**, not a shell. `npm run build` bundles the client, bundles
`src/entry-server.tsx`, then `scripts/prerender.mjs` renders each route and writes
`dist/<route>/index.html` with per-route `<title>`, description, canonical, OG/Twitter and
JSON-LD. `main.tsx` hydrates that markup rather than replacing it.

### One route table

`src/routes.tsx` is the single source of truth. `App.tsx`, `entry-server.tsx` and
`prerender.mjs` all consume it — the pre-renderer reads `PRERENDER_PATHS` out of the built SSR
bundle rather than keeping a copy.

This is a deliberate change from the template, whose README lists the fix as "not done yet". There,
three hand-maintained lists could drift, and a route the pre-renderer knew about but the server
router didn't fell through to the wildcard: its static HTML was written as the **404 page**,
`noindex`, wrong canonical, no content, and the build still printed a tick. It had already hit
three live service pages.

On top of the shared table the build now *verifies*: a route whose rendered canonical does not
match its own path fails the build with exit 1. Tested by removing a route from the server router
only, which produces

```
Build failed:
  - /insurance-claims: canonical is https://.../404, expected https://.../insurance-claims
```

`sitemap.xml` and `robots.txt` come from the same list, so a new page cannot ship missing from
the sitemap, and `noindex` pages are excluded by asking the renderer rather than by maintaining
a second exclusion list.

### Images

`src/data/images.ts` is generated by `build/assets.py` and maps each stem to the widths that
actually exist. `<Img stem="..." />` reads it and emits `srcset` plus intrinsic `width`/`height`.

Components name a stem, never a file. Sources here range from 540px to 2070px wide and nothing is
upscaled, so hardcoding `-1200.webp` in JSX produced 404s on every narrower source. That is why
the manifest exists.

Re-run `python ../build/assets.py` after adding source photos, then copy `web/assets/images` into
`public/assets/`.

## Local verification

`npm run serve` rather than `vite preview`. Preview serves the SPA shell for deep links, so every
page looks client-rendered and the thing the pre-render exists to prove is invisible; it also
binds IPv6-only on some Windows setups, which reads as a broken build. `scripts/serve-dist.mjs`
mirrors the production contract: `cleanUrls`, `trailingSlash: false` (308), and `404.html` with a
real 404 status.

## Layout

```
src/
├── routes.tsx          the route table
├── App.tsx             client router + per-route tracking
├── entry-server.tsx    SSR router, re-exports PRERENDER_PATHS
├── main.tsx            hydrate, attribution capture, phone tracking
├── index.css           design system tokens
├── lib/
│   ├── site.ts         every business-specific value, incl. the two placeholders
│   ├── attribution.ts  first-touch capture
│   ├── gtm.ts          dataLayer events
│   └── headStore.ts    head capture for the SSR pass
├── components/         PageMeta, Img, Navbar, Footer, QuoteForm
├── data/               services, gallery, images (generated)
└── pages/              one per route; ServicePage covers all six services
api/quote-photos.js     photo email, keyed by submission_id
```
